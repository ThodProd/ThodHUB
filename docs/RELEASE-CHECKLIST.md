# Выпуск приложения без ручной переноски файлов

1. Измените исходники. Поднимите версию `X.Y.Z` в проекте и hub/manifest.json. Не перезаписывайте старый release.
2. Соберите готовый Windows x64 пакет со всеми необходимыми runtime. В корне ZIP — manifest.json, без лишней родительской папки.
3. JSON: UTF-8 **без BOM**, например `[IO.File]::WriteAllText(path,json,[Text.UTF8Encoding]::new($false))`.
   Хаб также принимает BOM ради совместимости. Ошибка `0xEF is an invalid start` в старых версиях связана с BOM.
4. Пути в manifest и ZIP записывайте через `/`, без абсолютных путей, `..`, links/junction, зарезервированных имён Windows.
   Новая версия хаба нормализует Windows `\` в ZIP перед проверкой, но нормативный формат остаётся `/`.
5. Используйте scripts/package-module.ps1: он вычислит `size` в байтах и SHA-256, запишет URL и `notes`.
   Размер скачивания возле «Установить» берётся из `thodhub-release.json.size`, не из описания/README.
6. Обязательный минимум: успешная сборка и проверка, что hash/size/id/version/mode/API соответствуют пакету.
   Используйте `scripts/validate-package.ps1`. Пользователь может отложить функциональные тесты и скриншоты,
   но повреждённый или несобранный пакет публиковать нельзя.
7. Стабильный GitHub release `hub-vX.Y.Z` содержит ZIP и **точно** `thodhub-release.json`.
   Ни draft, ни prerelease не показываются как доступная установка. Notes только на русском, кратко по изменениям.
8. Новый проект регистрируется в main каталога один раз. Обновление версии обнаруживается без изменения каталога.
   Если изменились назначение, описание, шапка, имя или режим — обновите и каталог; сохраняйте чужие записи.
9. Изучите APP-STYLE.md: kind, description и artworkUrl обязательны для новых карточек. Не подставляйте случайную иконку вместо шапки.
10. Итог: ссылка на опубликованный выпуск, версия, что готово и кто проводит функциональную проверку.

## Зависимости при первом запуске
Предпочтительно включать переносимые зависимости в ZIP: .NET runtime, Python runtime, FFmpeg, библиотеки, модели.
Обычный пользователь не должен устанавливать SDK, pip, npm или искать файлы.
Если включить зависимость невозможно, сама программа реализует первый экран подготовки:
название отсутствующего компонента, зачем нужен, размер, кнопка «Установить», реальный прогресс и отмена.
Загружайте закреплённую версию с официального источника, сверяйте SHA-256, сохраняйте временно и активируйте после проверки.
Portable-файлы — в THODHUB_DATA_DIR/cache; системный установщик требует явной кнопки пользователя и штатного UAC.
При сбое покажите технический журнал и кнопку «Открыть официальный сайт», не запускайте пустой интерфейс с неработающими кнопками.
Длинную установку выполняйте через worker job.start/job.status, а не один RPC дольше 30 секунд.
Хаб не исполняет произвольные команды установки из каталога и не получает права администратора ради модуля.

11. При изменении системной интеграции проверьте реальную регистрацию, запуск из ярлыка при открытом хабе и обновление старой версии без удаления данных. Объявляйте integration + cleanup по MODULE-CONTRACT.md; не обещайте успех только по запуску процесса.

12. Для Open With проверяйте имя и EXE через SHAssocEnumHandlers: наличие ключа реестра ещё не подтверждает корректную ассоциацию. Для меню Windows 11 проверьте IExplorerCommand и регистрацию пакета. Проверьте работу при закрытом хабе, удаление интеграции и восстановление после установки. Подпись MSIX требует секретного ключа только у автора; публикуется лишь открытый CER, никогда PFX/ключ.
